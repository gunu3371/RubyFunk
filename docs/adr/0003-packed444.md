# 0003 — Packed 4:4:4 over a 4:2:0 carrier

Status: experimental implementation, 2026-11-07. Windows hardware validation pending.

## Path surveyed

| Stage | Existing path | Packed path |
| --- | --- | --- |
| Windows capture | IDD swap chain or WGC worker, BGRA/scRGB | Same RGB source |
| Conversion | `pf-encode-session::Targets`, video processor/P010 shader or AMF RGB CSC | `Packed444Converter`, before chroma filtering |
| Encoding | `pf-encode-win::amf`, NV12/P010 | Ordinary HEVC/AV1 4:2:0 at the coded size |
| Transport | Driver AU section, native packetizer, FEC and QUIC control | Same AU/media transport; layout in control messages |
| Apple decode | `VideoDecoder`, VideoToolbox, biplanar output | Hardware-required full-range NV12/P010 output |
| Presentation | `Stage2Pipeline`, `MetalVideoPresenter`, CSC/scaling | Integer-address Metal restore, then the same CSC/scaling |

The Windows driver and WGC worker share `pf-encode-session`; neither sends CPU RGB frames to
the host. Packing in the host's packetizer would be too late. The driver's captured-frame
notification keeps source dimensions; only the encoder-facing texture/frame uses coded dimensions.

## Decision

Use version 1 first. It permutes samples without prediction or pre-codec quantization.
Rubylight v2 keeps a 4:2:0 base and predicts other chroma samples; its residual quantization can
change a sample by one code before video compression. Its bitrate and motion tradeoffs need
separate measurements. Neither version makes HEVC/AV1 compression lossless. This feature has
no dependency on PyroWave.

Only macOS offers the new capability automatically, under the existing Full chroma preference,
for an eight-bit SDR session. The host selects it only on the resolved Windows AMF backend,
with HEVC or AV1, the existing host Full color policy enabled, and matching decoder limits. Linux, Windows, Android and browser clients do
not advertise restoration. Existing clients keep their existing path; an AMD host serves them
ordinary 4:2:0. No new player setting is added.

The backend candidate query lives on `Resolved`, following ADR-0002. AMF's size and throughput
limits are checked inside the actual session on the capture device, after encoder properties
are set. These per-session facts are not another process-global capability cache.

## Version 1 sample layout

Let `W = ceil(width / 64) * 64`, `H = ceil(height / 8) * 8`. The carrier is `W × 2H`.
Extend source pixels to `W × H` by repeating the last column and row, before taking parity.
There are three source planes, each full resolution. For source coordinate `(x,y)`:

| Source sample | Carrier plane | Carrier coordinate |
| --- | --- | --- |
| Y | Y | `(x,y)` |
| U, even x | U | `(x/2,y)` |
| V, even x | V | `(x/2,y)` |
| U, odd x | Y | `(floor(x/2),H+y)` |
| V, odd x | Y | `(W/2+floor(x/2),H+y)` |

Dense planar storage is Y (`2WH` samples), U (`WH/2`), then V (`WH/2`). NV12/P010 interleave
the last two planes; that storage change does not change the sample mapping. P010 stores
`code10 << 6` in each 16-bit word. The original crop is always the top-left `width × height`
of the restored planes. Restore with integer texel reads, before filtering, scaling or CSC.

`pf-packed444` is the dependency-free CPU oracle. Its geometry bounds are source 16384×8192;
those are arithmetic bounds, not a claim that hardware supports these sizes. GPU limits may
be much smaller. At 2304×1496 the carrier is 2304×2992: 6,893,568 pixels/frame,
827,228,160 pixels/s at 120 Hz, or 3,231,360 rounded 16×16 macroblocks/s.

## Wire extension

RubyFunk uses native feature bit 120 and field tag 128. These are fork allocations, not
reservations in upstream rubyfunk. Keep them consistent when merging future upstream tags.
`FEATURE_STREAM_CONFIG` and `FEATURE_FORMAT_EPOCH` must also be negotiated.

| Message | Field 128 |
| --- | --- |
| ClientHello | 18-byte capabilities |
| ServerHello | 17-byte selected layout, omitted for ordinary video |
| StreamConfig | Same selected layout for that epoch, omitted for ordinary video |

Capabilities: version mask `u8` (bit 0 = v1), mode mask `u8` (HEVC8=1, HEVC10=2,
AV1-8=4, AV1-10=8), maximum coded width `u32`, height `u32`, pixels/s `u64`; integers LE.
Zero limits are unknown and admit nothing. Unknown version bits do not enable v1.
Selected layout: version `u8`, source width/height `u32`, coded width/height `u32`, all LE.
Reject unknown versions, wrong lengths and inconsistent padded dimensions.

Depth and source CICP remain in the existing video format fields. `chroma_format=1` describes
the carrier, not the restored full-chroma image. Only HEVC/AV1 at 8 or 10 bits may carry a
layout. ServerHello seeds the first epoch with its layout before any AU can be handed out;
the ordinary Welcome-only format must not overwrite it. Subsequent formats follow the existing
epoch barrier. The C ABI getter moves with the newest AU, alongside colour/codec getters.

The carrier is **full range**, including when the source samples are studio range. Odd-column
Cb/Cr stored in Y must not be expanded, clipped as studio luma or interpolated by a decoder's
colour converter. AMF must accept full-range input/output properties; VideoToolbox must return
full-range biplanar buffers. The presenter uses the source's control-channel CICP and range.
It snapshots those fields into each decode's frame context and pixel-buffer attachment.

Input coordinates, display topology, aspect ratio and layout all use source dimensions.
The Apple intake reports source dimensions; Metal sizes its restored planes to that crop.
Packed sessions currently reject live mode/codec changes and extra screens. Reconnect to
change the mode. A source-size/depth change that escapes this gate fails the encoder request.
Raw packed planes never reach the sample-buffer display layer or the late-latch shader.

## Admission and failure

AMF checks `GetInputCaps` width/height ranges and `HevcMaxThroughput` or
`Av1CapMaxThroughput` in 16×16 macroblocks/s, then opens at the coded dimensions and requested
rate. Reported limits do not guarantee sustained fps under shared GPU load.
Unknown limits or a refusal end the packed session with a logged cause; the backend list
cannot fall through to a converter that emits ordinary video under a packed label. Disable
Full chroma or lower the mode to reconnect with ordinary video.

Apple probes hardware-required decoder session creation at the exact coded dimensions and
compiles the restore pipeline before offering it. HEVC uses a locally encoded format;
AV1 uses a generated Main 8-bit 4:2:0 sequence description. Session creation is an admission
check, not proof of 120 fps. The advertised rate is the requested admission budget; VideoToolbox
exposes no reliable sustained-throughput limit here. The real stream still needs the decode
benchmark. The existing hardware-only decode failure backstop also applies to packed HEVC.

Automatic offer/host selection stays eight-bit SDR. The oracle, fixtures, HLSL and Metal kernels
handle ten-bit samples, but ten-bit SDR/HDR streaming, static metadata, source gamut, HDR mode
changes and decoder range preservation need end-to-end verification before advertising them.

## Other clients

Implement the same integer reads using D3D11 plane SRVs, Vulkan plane views, or GL `texelFetch`.
Bypass automatic YCbCr sampler conversion and chroma siting correction until after restoration.
MediaCodec external RGB textures and browser external video textures are insufficient when
they hide the raw planes or apply CSC first. Such clients must keep the capability absent.
Run the shared vectors before advertising any codec/depth. Keep decoded and restored geometry
separate, and retain per-frame layout/colour through decoder and render queues.

## Compatibility changes

Network ALPN stays unchanged and optional fields preserve old peers. The C ABI is 66 with an
append-only, size-guarded capability tail and an additive layout getter. Build matching Apple
headers/libraries. Driver protocol is 10 and worker protocol is 2: an older implementation can
misinterpret chroma request 2 as ordinary 4:2:0. Install the matching Windows host, driver and
worker together. Application and bundle identifiers remain unchanged.
